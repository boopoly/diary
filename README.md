# 마음결 — 감정 일기

하루의 감정과 짧은 기록을 남기고 돌아볼 수 있는 감정 일기입니다. 데이터는 Supabase에 저장되어 같은 프로젝트에 연결된 다른 기기와 브라우저에서도 확인할 수 있습니다.

## 소개

- 기쁨, 평온, 슬픔, 화남, 불안 중 하나를 고르고 일기를 작성합니다.
- 기록은 최신순으로 표시되며 감정별로 필터링하거나 삭제할 수 있습니다.
- 로딩, 저장 중, 오류, 기록이 없거나 필터 결과가 비어 있는 상태를 화면에 표시합니다.

## 어떻게 만들었나요

Copilot Plan 모드에서 요구사항과 데이터 구조를 계획한 뒤 Agent로 구현했습니다. 화면은 Vite와 React로 구성하고 Tailwind CSS Vite 플러그인으로 스타일링했습니다. Supabase 클라이언트 생성은 `src/lib/supabase.js` 한 곳에 두고, `src/api/diaries.js`에 조회·추가·삭제 함수를 분리해 화면에서 데이터베이스 코드를 직접 다루지 않도록 했습니다.

## 데이터는 어디에 저장되나요

일기 데이터는 Supabase의 `public.diaries` 테이블에 저장됩니다.

| 컬럼 | 설명 |
| --- | --- |
| `id` | 데이터베이스가 자동 생성하는 일기 식별자 |
| `content` | 필수 일기 내용 |
| `emotion` | `joy`, `calm`, `sad`, `angry`, `anxious` 중 하나 |
| `created_at` | 데이터베이스가 자동 생성하는 작성 시각 |

브라우저의 `localStorage`에 저장하는 방식과 달리 Supabase에 기록하므로, 같은 Supabase 프로젝트를 사용하는 기기와 브라우저에서 목록을 불러올 수 있습니다. 새 기록은 페이지를 새로고침하거나 다시 열었을 때 반영됩니다.

## 보안에서 확인한 것

Supabase URL과 Publishable key는 프로젝트 루트의 `.env.local`에 설정합니다. 이 파일은 `.gitignore`에서 제외되며, 저장소에는 실제 값 대신 `.env.example`만 둡니다. 브라우저에서 실행되는 앱에는 환경변수가 포함되므로 Publishable key는 개발자 도구에서 확인할 수 있습니다. 이 키는 공개를 전제로 하며, Secret key나 `service_role` 키를 프론트엔드에 넣으면 안 됩니다.

현재 실습용 RLS 정책은 익명 사용자의 읽기·작성을 허용하고, 모든 기록의 삭제도 허용합니다. 따라서 이 앱은 로그인 없는 **공용 일기장**이며, 사이트에 접근할 수 있는 누구나 기록을 읽고 삭제할 수 있습니다. 개인적인 내용을 저장하는 용도로는 사용하지 마세요. 개인별 일기장으로 바꾸려면 Supabase Auth, 사용자 식별 컬럼, 사용자별 RLS 정책을 추가해야 합니다.

## 실행 방법

1. 의존성을 설치합니다.

	```bash
	npm install
	```

2. `.env.example`을 복사해 `.env.local`을 만들고 Supabase 프로젝트 값을 입력합니다.

	```bash
	cp .env.example .env.local
	```

	`VITE_SUPABASE_URL`에는 Project URL을, `VITE_SUPABASE_PUBLISHABLE_KEY`에는 Publishable key를 입력합니다. `diaries` 테이블과 실습용 RLS 정책은 Supabase에서 미리 설정되어 있어야 합니다. 자세한 순서는 [`guide.md`](./guide.md)를 참고하세요.

3. 개발 서버를 실행합니다.

	```bash
	npm run dev
	```

4. 프로덕션 빌드를 확인하려면 다음 명령을 실행합니다.

	```bash
	npm run build
	```

배포 주소: 아직 배포되지 않았습니다. Netlify 배포 후 이 항목을 갱신합니다.
